# 更新日志编辑规则

本规则管两份文件：

| 文件 | 职责 | CI |
|---|---|---|
| `CHANGELOG_UNRELEASED.md`（根目录） | **未发布的累计调整**：开发期唯一要动的文件，它就是下一个版本发布说明的草稿 | 不读 |
| `CHANGELOG.md`（根目录） | **已发布内容的留档**：版本段会被 CI 取出作为发布说明 | 读（release workflow 的 Collect changelog 一步） |

## 一、结构（CI 硬约束）

### 未发布文件

- 首行 `# 未发布改动`，随后一行说明它跟 `CHANGELOG.md` 的关系。
- 唯一的段落标题是 `## [未发布]`，不带日期。小节只能用 `###`，名与顺序同第二节。

### 留档文件

- 首行 `# 更新日志`。
- 版本段一律 `## [<版本>] - <YYYY-MM-DD>`：版本号不带 `v` 前缀，日期是发布当天。
- **`## [` 是段落边界**：CI 从版本段标题的下一行开始取，遇到下一个行首 `## [` 停止。正文里不许出现行首 `## [`。
- 留档文件里不再出现 `## [未发布]`：待发内容住在上面的文件里。

### 发版时（按顺序做完四步）

1. 把 `CHANGELOG_UNRELEASED.md` 里 `## [未发布]` 那一整段搬到 `CHANGELOG.md` 顶部，
   标题改成 `## [<版本>] - <YYYY-MM-DD>`（日期用当天）。
2. 把 `gradle.properties` 的 `mod_version` 改成同一个版本号。
3. 把 `CHANGELOG_UNRELEASED.md` 清回骨架：标题、说明、空的 `## [未发布]`。
4. 已发布的版本段此后不再增减条目（边界见第二节末）。

## 二、小节：固定六个，顺序固定（两份文件同一套）

| 序 | 小节 | 收什么 | 句首动词 |
|:--:|------|--------|----------|
| 1 | 新增 | 玩家此前拿不到的东西 | 新增 |
| 2 | 支持 | 接进了别的模组或格式 | 支持 |
| 3 | 改进 | 已有的东西变好 | 改进 |
| 4 | 修复 | 此前是错的 | 修复 |
| 5 | 调整与依赖 | 有意为之的改动与版本下限 | 调整 |
| 6 | 更正 | 这份文档历史段落里写错的描述 | 更正 |

- 没内容的小节整节不写。代码的错归「修复」，文档的错才归「更正」。
- 留档文件里已封版的段落是归档，**不再增减条目**：只允许修正错别字、标点与格式瑕疵，
  且不得改变条目内容与含义。发现归档段落事实写错了，写进 `CHANGELOG_UNRELEASED.md` 的「更正」小节。

## 三、条目

- **一行一条**：`- ` 开头，不换行、不套子列表。
- **一句短话，只讲事实**：多数条目 30 字上下，最长不超过 135 字节（约 45 汉字）。
  不写「此前…现在…」对照，不写成因，不写副作用，不写实现机制。
- **只写上一已发布版本玩家能遇到的事**：同一版开发过程中自己引入又自己修掉的问题不写。
- **句首复用小节名当动词**：「新增…」「修复…」「改进…」「调整…」。
- **加粗只给被改动的对象**，一条一次，加粗名词短语而非语气词。
- 标点用全角，引号用「」，代码与文件名用反引号；不写 emoji、表格、截图、链接。

## 四、依赖下限的写法

放在「调整与依赖」末尾，句式固定：

```
- 调整 Thaumaturge 最低版本为 **1.1.0**（示例值，只示意句式）
```

只列**本次发版变动的**硬线下限（写进 `neoforge.mods.toml` 的 `versionRange` 的那些）。

## 五、发版前自检

- [ ] `grep -c '^- ' CHANGELOG_UNRELEASED.md` 为 0：没漏搬的条目
- [ ] `git diff CHANGELOG.md` 只多出一段，`git diff CHANGELOG_UNRELEASED.md` 只少掉条目
- [ ] `grep -n '^## \[' CHANGELOG.md`：行首 `## [` 只出现在版本段标题
- [ ] 小节名与顺序符合第二节；无空小节、无裸列表（只查本次要发的版本段）
- [ ] 每条目句首动词与小节一致；一行一条、只讲事实
- [ ] 每条都属上一已发布版本玩家能遇到的变化
- [ ] 变动的硬线下限已写进「调整与依赖」
